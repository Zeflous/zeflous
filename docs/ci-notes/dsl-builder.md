# CI Notes — DSL Builder (The Triad, langkah 4)

Decision record untuk lane DSL Builder di bawah **Configuration System** (`src/Zef/Framework/Config/Routing/`). Dokumen ini melengkapi `docs/ci-notes/config-system.md` (KDD-1..7) dan `docs/ci-notes/radix-engine.md` (KDD-R1..R9, termasuk amendemen R5 oleh lane ini).

## KDD-D1..D8

- **D1 (kontrak kompilator)**: DSL = kompilator deklarasi → array Standard Route Schema polos ("bahasa induk"). Output wajib lolos `RouteSchema::assertList()` DAN langsung dikonsumsi `RadixTree::compile()` — dibuktikan test integrasi satu arah penuh: declare → assert → compile → match (params + 405 + notFound) → `route(name)` → generate→match round-trip. Tidak ada jalur output lain, tidak ada registrasi langsung ke tree.
- **D2 (middleware forward-flow scoped)**: deklarasi `middleware()` dalam scope menempel pada pendaftaran SETELAH deklarasi itu dan diwariskan group yang dibuka setelahnya; group entry meng-snapshot state (`RouteDslSnapshot`) dan exit memulihkan lewat `try/finally` — termasuk saat closure melempar (test: exception terpropagasi + pendaftaran berikutnya tanpa prefix/middleware bocor). Urutan final = global → group (luar→dalam) → route-level. Tidak ada "pending group middleware" stateful.
- **D3 (prefix)**: komposisi di titik deklarasi via `RoutePrefix::concat` (hasil identik dengan merge-saat-group-ditutup, kegagalan lebih dini & menunjuk baris deklarasi). Semantik root-`/`: prefix `/` = no-op; path `/` dalam group = prefix itu sendiri — trailing slash tak pernah dihasilkan. Prefix boleh berparameter (`group('/users/{user}')` sah — grammar menilai path komposit). Validasi bentuk prefix: non-empty, leading `/`, tanpa trailing `/` kecuali root.
- **D4 (satu titik kebijakan)**: DSL TIDAK menduplikasi kebijakan engine — duplikasi pola/nama/method-overlap (registry), dedupe+sort method (CompiledRoute), compilability+anchoring constraint (RouteConstraints) tetap milik engine. DSL hanya menjamin: bentuk schema, grammar path (via `RoutePath::parse` — pemilik tunggal grammar), nama constraint ⊆ nama parameter (defense-in-depth deklaratif: error di baris deklarasi, kebijakan tetap milik engine), deklarasi non-empty, declare-once. Keputusan nama: hanya non-empty string (regex legacy `[A-Za-z0-9._-]{1,128}` TIDAK diadopsi — kebijakan nama milik engine non-empty). Budget route legacy (10000) juga tidak diadopsi — tanpa padanan engine, tak ada alasan menolak deklarasi besar.
- **D5 (declare-once vs append)**: `name`/`where`/`meta` sekali per rute (deklarasi kedua = rute ambigu, bukan merge — pesan eksak menyebut pola + nilai pertama); `middleware` append-only karena stacking adalah fiturnya. Method di-`mb_strtoupper` di `match()` (normalisasi deklarasi — unicode 'gét'→'GÉT'); verb memancarkan konstanta uppercase; dedupe/sort TIDAK (milik engine).
- **D6 (resource macro)**: 7 entri — index/create/store/show/edit/update/destroy dengan `update` = SATU entri [PUT, PATCH] (set method, bukan dua rute); handler `Controller@action`; nama basis = segmen statis path di-join `.` (parameter dibuang: `/users/{user}/posts` → `users.posts.*`); hanya `{id}` (satu-satunya parameter yang diciptakan makro) yang bisa di-constrain — kunci lain ditolak eksak; path root / semua-parameter ditolak (tak bisa menamai resource). Ekspansi mendaftar lewat API publik façade (`match()` + `name()` + `where()`) → prefix/middleware inheritance + seluruh validasi deklaratif berlaku gratis.
- **D7 (builder mutable by design)**: sesi deklarasi single-threaded mutable — `RouteDsl` façade @api dengan state di `RouteDslScope` (@internal; preseden `RouteTreeBuilder` mutable → hasil beku polos). `toArray()` idempoten (snapshot); sesi tetap bisa lanjut setelahnya. Kelas dibagi demi archeology D≤20: Scope (state + draft + freeze), Snapshot (VO restore), Methods (normalisasi set method), Constraints (validasi map), Fields (trio declare-once), Middleware (stack append-only).
- **D8 (bench jujur)**: `RouteDslBench` — biaya `define()` LINEAR per rute (setiap deklarasi membawa validasinya) dan dibayar SEKALI saat build/cache; flatness runtime match adalah klaim `RouterBench`, tidak diulang. Bukan klaim menang-kalah: deklarasi fluent membeli validasi + fail-closed, harganya yang diukur.

## Temuan lintas-lane: engine method-disjoint (amendemen R5)

Menyusun makro resource menemukan konflik desain: engine #229 menolak pola kanonik sama secara mutlak, padahal model skema = satu entri per deklarasi method (REST: `GET /photos`→index vs `POST /photos`→store, handler berbeda). Amendemen (PR terpisah sebelum makro): rute boleh berbagi pola kanonik **dengan set method disjoint**; klaim method dua kali = ambigu → ditolak (`RouteMethodClaims`, pesan menyebut method + pola pemilik pertama). Leaf node menyimpan `list<CompiledRoute>`; `LeafRoute::accepting()` mengembalikan kandidat yang lolos constraint per rute (kegagalan constraint satu rute tidak mematikan tetangganya); `RouteMethodAnswer::resolve()` memilih jawaban method + menyusun union 405 terurut-unik; zipper parameter di `RouteParameters`. Rincian di `docs/ci-notes/radix-engine.md` §R5.

## Pola teknis yang terbukti (dibawa ke lane berikutnya)

- **Yardstick archeology lokal ≠ CI**: metrik Halstead-D sensitif terhadap data git (churn) — checkout CI dangkal (`gitTotalCommits=1`) mengukur file yang berubah di branch ~+2.4 D vs lokal ber-history; SEBALIKNYA pengukuran lokal dapat naik sendiri setelah file diedit berulang (churn lokal). Pre-flight andal: **shallow clone** (`git clone --depth 1 --branch <branch>`) + vendor disalin + jalankan `vendor/bin/phpcodearcheology` — mereproduksi yardstick CI; targetkan D ≤ 17.5 untuk file baru/berubah.
- **Inline > split-method untuk Halstead-D**: method bantu kecil dengan operand berulang ($routes/$method/$route) MENAIKKAN D justru saat "dirapikan" (RouteMethodAnswer: 26.25 split → 15.17 inline). Perbatasan method bukan pengencer D; pengencer D = operan berbeda (const bermakna) & lebih sedikit repetisi.
- **`array_values(array_filter(...))` mengundang mutan UnwrapArrayValues** yang tak terbunuh dari konsumen foreach — bentuk loop+continue atas list in-memory deterministik (urutan tetap), beda dengan loop atas filesystem yang urutannya tidak.
- **Rector + closure bersarang**: `RenameVariableToMatchMethodCallReturnTypeRector` merename parameter closure LUAR tapi tidak body closure DALAM yang menunjuk variabel luar → "Call to a member function on null". Karena `group()` mengirim façade yang SAMA, penamaan param konsisten `$routeDsl` di semua level (shadowing) adalah fix yang stabil terhadap rector.
- **PHPUnit 13 + phpstan**: `assertInstanceOf` pada kelas final = `alreadyNarrowedType` error — asertikan perilaku yang dapat diamati, bukan tipe yang sudah dijamin statis.
- **Slevomat phpcs**: docblock properti satu-baris (RequireOneLinePropertyDocComment — phpcbf auto-fix); `EarlyExit` menuntut bentuk continue — jangan melawan fixer, pilih bentuk yang lolos keduanya (lihat pola filter/LintReport di #240).

## Atribusi

Pola desain (bukan kode — zero-dependency doctrine tetap: `require` hanya `php: ^8.4`) diinspirasi implementasi terbukti pada repo legacy `Zeflous/zef-framework`: `RouteDefinition` (fail-closed constructor validation: method upper-case, path wajib leading `/`, handler non-empty — diadopsi sebagai validasi deklaratif DSL), `RouteCollection` (disiplin deklarasi terdaftar + nameIndex; nameIndex TIDAK diadopsi di DSL karena kebijakan keunikan nama milik engine — satu titik kebijakan). Macro resource mengikuti konvensi CRUD framework umum (7 aksi, update = PUT|PATCH) sebagaimana dirumuskan ROADMAP §2.D.
